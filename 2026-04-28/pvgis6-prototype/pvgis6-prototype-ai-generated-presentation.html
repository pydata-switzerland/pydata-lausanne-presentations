PVGIS 5: valuable, but fragile

🧠

Impact was real

Your draft keeps the historical contribution visible: PVGIS 5 already delivered useful public-facing solar estimates and built trust with users.

👤

Bus factor was not

You explicitly note Thomas Huld and a “100% bus factor”, which is a sharp way to explain why maintainability became a strategic issue.

🧱

Legacy engine constraints

The README states PVGIS 6 is intended to replace the legacy internal C/C++ engine behind the public service.

🔄

Why redesign

The migration is not a cosmetic rewrite; it is about openness, reproducibility, extensibility and a healthier contributor model.

Data pipeline: one-off prep, then fast per-pixel work

One-off processing
  • Collect climate and irradiance data.
  • Rechunk into spatially efficient stores.
  • Persist as Zarr for downstream reuse.
Per-location processing
  • Fetch multiple time series at coordinates (x, y).
  • Use Xarray-backed arrays with NumPy kernels.
  • Run photovoltaic analysis and export JSON or CSV.

This split is the engineering heart of the talk: expensive restructuring happens once, while interactive calculations stay responsive afterwards.

Data models: YAML first, Python generated

  • Scientific entities are defined once in YAML.
  • Recursive loaders resolve require: inheritance chains.
  • A generation step builds consolidated Python definitions.
  • Runtime factories emit Pydantic models and structured outputs.
name: DataModelTemplate label: Data Model Template require: - attribute/name - attribute/title - attribute/value - attribute/unit - attribute/algorithm - metadata/data_source

This is one of the most technically interesting parts of the README because it separates domain knowledge editing from engine implementation.

Why this data-model pattern is compelling

🧪

Scientists can edit models

Field names, units, dependencies and metadata live outside Python source code.

🛡️

Factories enforce contracts

The runtime layer validates types, required fields, shapes and ranges before calculations proceed.

🔁

Outputs stay synchronized

The same definitions drive API responses, CLI output and documentation structure.

📉

Trade-off is explicit

The README openly admits a learning curve and debugging cost in exchange for transparency and long-term flexibility.
